# 컬러메이트 (Color Mate)

학생이 **퍼스널컬러 컨설턴트 · 메이크업 아티스트 · 패션 스타일리스트** 를 체험하는 학교 진로체험용 웹앱입니다.

## 활동 흐름

| 단계 | 화면 | AI 비용 |
| --- | --- | --- |
| 1 | 수업코드 + 이름 입력 | 0원 |
| 2 | 시각 선택 질문 10개로 퍼스널컬러 사전 예상 | 0원 (웹앱 내부 점수 계산) |
| 3 | 예상 결과 (온도 · 명도 · 채도 축) | 0원 |
| 4 | 선생님과 실제 드레이핑 (오프라인) | 0원 |
| 5 | 12타입 중 최종 타입 확정 | 0원 |
| 6 | 얼굴 + 어깨가 보이는 정면 사진 1장 준비 | 0원 |
| 7 | 메이크업 LAB (내 사진 위에서 디자인) | 0원 |
| 8 | 의상 · 신발 · 액세서리 스타일링 | 0원 |
| 9 | AI 최종 스타일 → Before/After → 컬러 프로필 | **OpenAI 이미지 생성 1회** |

유료 AI 호출은 마지막 `AI로 내 스타일 완성하기` 버튼 **1회**에서만 실행됩니다. 미리보기 단계에서는 어떤 AI API 도 호출하지 않습니다.

## 12타입 퍼스널컬러

봄(라이트 · 브라이트 · 웜), 여름(라이트 · 뮤트 · 쿨), 가을(뮤트 · 웜 · 딥), 겨울(브라이트 · 쿨 · 딥) 12타입을 운영합니다.
타입마다 대표 팔레트 · 추천 립 · 블러셔 · 아이섀도 · 의상 색 · 온도 · 명도 · 채도 · 키워드가 각각 다르게 정의되어 있습니다. (`src/data/personalColors.ts`)

추천색에는 `★ 내 타입 추천` 표시가 붙지만 **다른 타입 색도 자유롭게 선택**할 수 있습니다. 추천색과 다른 색을 직접 비교해 보는 것이 활동의 목적입니다.

## 실행

```bash
npm install
npm run dev      # 개발 서버
npm run build    # 타입체크 + 프로덕션 빌드
npm run lint     # ESLint
```

## 교사용 화면

- `/expert` — 교사용 관리센터 (4자리 비밀번호)
- `/settings` — OpenAI 이미지 API 설정

관리센터에서 **학교 / 기관명 + 반 / 회차** 를 입력해 수업코드를 여러 개 만들고 복사 · 삭제할 수 있습니다.
수업코드는 현재 브라우저의 `localStorage` 에 저장되며, 저장 구현은 `src/services/classSessions.ts` 의 `ClassSessionStore` 인터페이스 뒤에 분리해 두어 나중에 서버 저장으로 교체할 수 있습니다.

교사가 학생의 퍼스널컬러를 미리 등록하는 기능은 없습니다. 학생이 직접 예상하고 드레이핑으로 확인한 뒤 확정합니다.

## OpenAI 설정

API 키는 브라우저 입력창이나 `VITE_` 환경변수에 넣지 않습니다. Vercel 프로젝트의 **Settings → Environment Variables** 에 등록한 뒤 재배포하세요.

```text
OPENAI_API_KEY=발급받은 OpenAI API 키
SETTINGS_PIN=교사용 4자리 비밀번호
SETTINGS_ENCRYPTION_KEY=24자 이상의 길고 예측 불가능한 임의 문자열
OPENAI_IMAGE_MODEL=gpt-image-1.5
OPENAI_IMAGE_QUALITY=medium
OPENAI_IMAGE_SIZE=1024x1536
```

`/settings` 화면에서 저장한 키는 암호화된 HttpOnly 쿠키에 보관되며 저장에는 `SETTINGS_ENCRYPTION_KEY` 가 필요합니다. 여러 기기에서 학생이 접속하는 운영 방식이라면 서버 환경변수 `OPENAI_API_KEY` 를 사용하는 편이 안정적입니다.

## 사진과 개인정보

- 필요한 사진은 **얼굴 + 어깨가 보이는 정면 사진 1장** 입니다. 전신사진은 요구하지 않습니다.
- 사진은 브라우저 메모리에만 두고, 마지막 AI 생성 1회에서만 API 로 전송합니다.
- 최종 이미지는 얼굴 · 헤어 · 피부톤을 유지하며, 사진에 없는 몸은 학생 연령에 맞는 자연스러운 비율로 구성합니다. 실제 키나 체형을 재현하지 않습니다.

## 화면 구조

```
src/
  data/         12타입 · 질문 · 메이크업 · 의상 카탈로그 · 활동 단계 정의
  services/     수업코드 저장소, 학생 세션 저장
  screens/      화면 단위 컴포넌트
  components/   공용 UI (활동 진행바, 색상칩, 메이크업 미리보기 캔버스)
  styles/       tokens → base → components → screens (@layer 로 우선순위 고정)
api/            Vercel Functions (최종 이미지 생성 · 설정)
```

## 반응형

`src/styles/tokens.css` 한 곳에서 브레이크포인트별 폭 · 여백 · 글자 크기 토큰을 정의하고, 화면 CSS 는 토큰만 사용합니다.

| 구간 | 폭 | 레이아웃 |
| --- | --- | --- |
| 모바일 | ~767px | 1열, 본문 14~16px |
| 태블릿 | 768~1179px | 좌우 여백 32px, 필요한 곳 2열, 본문 15~17px |
| 노트북 이상 | 1180px~ | 콘텐츠 최대 1320~1480px, 스튜디오 2열(사진 / 컨트롤), 본문 16~18px |

한글 가독성을 위해 전역으로 `word-break: keep-all`, `overflow-wrap: break-word` 를 적용하고 제목은 `text-wrap: balance`, 본문은 `text-wrap: pretty` 를 사용합니다. 강제 `<br>` 줄바꿈은 사용하지 않습니다.
